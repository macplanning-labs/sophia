# リリース運用（Sophia OSS）

WIP（`macplanning-labs/wip`）と同型の最小ルールです。

## SemVer

| 種別 | いつ |
| --- | --- |
| MAJOR | 互換を破る API / 必須マイグレーションが利用者作業を強いるとき |
| MINOR | 後方互換の機能追加 |
| PATCH | バグ修正・依存の安全な更新・ドキュメントのみ |

## 手順

1. 変更を要約（Added / Fixed / Security）
2. `CHANGELOG.md` を更新
3. タグ `vX.Y.Z` を打ち、GitHub Release を作成（**秘密・PII・社内票番・実データは書かない**）
4. `cargo audit` / `npm audit` / gitleaks（必要時）を通し、結果は件数と重大度のみ記録

## 書いてはいけないもの

- APIキー・トークン・接続文字列・`.env` 実値
- 取引先名・契約条件・個人情報
- 社内限定の本番 URL＋認証の組
